# Epic: Cart

Phase 4 · repository `shop-web` · areas `contract-client`, `cart`, `auth`, `e2e` · tracking issue:
_created with this PR_

## Goal

Build the cart page `/cart` to its artboard (`design/Cart.dc.html`) with the render strategy tagged
on it: a static shell, the cart streamed by the Next.js server with a 250 ms budget and handed to
the client through `HydrationBoundary`, the client falling back to the cart persisted in IndexedDB
and then to a skeleton, a stale banner with retry when the backend cannot be reached, and
quantity changes applied optimistically and sent as one `PATCH` per 400 ms burst. The guest cart is
merged into the user cart after login. Backed by shop-api's Cart epic (Phase 4), contract `1.3.0`.

## Scope

In scope:

- Pin `@shop/api-contract` `1.3.0` (the release of shop-api's Cart epic), regenerate types.
- MSW handlers and fixtures for all seven cart operations, built from the artboard and the shop-api
  seed numbers, with scenario overrides (slow, 503, limits, empty).
- In `src/features/cart/`: the full-cart query (persisted), the server fetcher with its budget, the
  cart section, the cart view with its four states (loaded, skeleton, stale, empty), line items,
  the quantity stepper with debounce, remove, line selection and the summary panel.
- The route `src/app/(shop)/cart/page.tsx` (static shell; no `loading.tsx`, the hole has its own
  `<Suspense>`).
- The header badge and the add-to-cart button stay consistent with the full cart (one cache).
- Guest cart merge after a successful login, composed in `app/` (features never import each
  other).
- Playwright journeys for the cart (desktop and phone, axe), including a slowed and a failing
  backend.

Out of scope: vouchers (the artboard's "Mã giảm giá" box has no contract operation; open question
1); shipping fees (Checkout, Phase 5); the checkout page and passing the selection to it beyond the
link (Checkout, Phase 5); the `cart_count` hint cookie and feature flags (Peak readiness, Phase 6);
Lighthouse budgets (Phase 6); "Lưu để mua sau", wishlist and recommendations on the cart page (not
on the artboard).

## Decisions

See `docs/handoff/technical-notes.md` § 1 (state ownership), § 3 (caching rules: user data is never
cached in Next.js), § 4 (cart page: stream with a budget, fall back to the client) and § 7 (time
budgets). Before using `Suspense` holes with `cookies()` under `cacheComponents`, `HydrationBoundary`
or the persister, read `node_modules/next/dist/docs/` and the TanStack Query v5 docs for
`PersistQueryClientProvider` (do not rely on memory).

## Contract impact

None from shop-web. It consumes `1.3.0` from shop-api's Cart epic: `CartItem.listPrice` and
`stockLevel` (struck price and stock line), `CART_ITEMS_LIMIT` (mapped in the error messages as
"Giỏ hàng đã đủ 50 sản phẩm"), and 401 on cart operations. Through the gateway the 401 comes from
`cart-service` when the browser sends the `logged_in=1` hint without a valid access cookie (the
cookie expired after 10 minutes; owner decision 2026-11-24, shop-api Cart epic § Identity), so an
add-to-cart or quantity change after an idle tab never lands in a guest cart: the existing
single-flight refresh in `src/lib/api` runs and the request is retried with the new token. A failed
refresh runs the session-expired flow (Phase 2), which clears the hint, so the next attempt is a
guest write. No shop-web code change is needed for this beyond tests. Until `1.3.0` is released, tasks after task 1 cannot start.

## Risks and mitigations

| Risk                                                        | Mitigation                                                                                                                                                                                                |
| ----------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| The cart hole holds the stream                              | Hard 250 ms budget in `serverApi`; a test with a 1 s MSW delay asserts the page streams and the client takes over.                                                                                        |
| A persisted cart from another user is shown                 | Logout removes the persisted cache (Phase 2); the persisted cart is only a fallback and is replaced by the first successful fetch. A test logs in as user B after user A's logout and sees no lines of A. |
| Debounce loses the last change (tab closed)                 | Pending changes are flushed on `pagehide`; the server answer replaces the optimistic state.                                                                                                               |
| Out-of-order responses overwrite newer optimistic values    | A response for a SKU is applied only when no newer change for that SKU is pending (per-SKU sequence number); tested with a delayed first `PATCH`.                                                         |
| Hydration mismatch between SSR data and the restored cache  | Hydrated data wins (newer `dataUpdatedAt`); `CartView` renders the skeleton until restoring has finished only when nothing was hydrated.                                                                  |
| User data in a shared cache                                 | No `'use cache'` in the cart feature; a unit test fails when a file in the feature contains `'use cache'`.                                                                                                |
| An expired access token turns cart writes into guest writes | `cart-service` answers 401 when `logged_in=1` is sent without a token; tested with MSW (401 → one refresh → retried `POST /api/cart/items` lands in the user cart) and in e2e with the real gateway.      |
| Merge failure blocks login                                  | `onLoggedIn` errors are swallowed and logged; tested with a 503 merge.                                                                                                                                    |

## Open questions for the owner

1. **Voucher box.** The artboard shows "Mã giảm giá" with "SALE1212 (−120.000₫)", but the contract
   has no voucher operation and the plan's MVP has none. Proposed: do not render the box or the
   voucher row in Phase 4. Alternative: render it disabled with "Sắp ra mắt".
2. **Shipping row.** The artboard says "Phí vận chuyển: Miễn phí" while shipping options are chosen
   at checkout (`listShippingOptions`, Phase 5). Proposed: keep "Miễn phí" as on the artboard.
   Alternative: "Tính ở bước thanh toán".
3. **Error with nothing saved.** No artboard state covers "backend down and no saved cart".
   Proposed: the empty-cart frame with the error text and "Thử lại".

## Done when

- `/cart` matches the artboard in the `loaded`, `skeleton` and `stale` states and the empty state
  at 1280 px, and stacks at 390 px, with axe passing (Playwright).
- With the cart backend delayed past 250 ms the page still streams, and the client shows the cart;
  with the backend failing after a saved visit the stale banner and retry are shown.
- Five clicks on "+" within 400 ms send exactly one `PATCH` with the final quantity, and an error
  rolls the line back.
- A guest's lines are in the user cart after login.
- After the access cookie expires, "Thêm vào giỏ" refreshes the session once and the item is in the
  user cart (not a guest cart).
- A merge that takes longer than 1 s does not delay the redirect after login by more than 1 s.
- `next build` reports `/cart` as partially prerendered; `make lint test e2e` is green on `main`.
